## 0. 体验宪章（最高优先级）
**复杂留给系统，不留给用户。** 每个界面决策都要过这 8 条：
1. **系统能判断的，不留给用户。** 市场、语言、渠道、受众、语气由资料推断。资料写得明确的事实不逐条点选。安全的修订直接做。
2. **此刻没用的，就不出现。** 不出现版本号、内部编号（F-01、R-03、W-1）和接口名。额度、Trace、获取方式只在影响结果时，就近说明。
3. **能替人做的，就直接做。** 一键跑完全流程。没有依据的夸大说法直接删掉或改写。知乎建议默认启用。改动后自动复查。检查报告和口径表自动附带。
4. **同一件事，处处一样。** 一个概念只有一个名字（见 §7 术语表）。颜色语义固定：琥珀 = 需要你，绿 = 系统已处理或已完成，红 = 风险或已拦下，石板灰 = 演示或说明。
5. **按下去有回应，再按能收回。** 每个写操作都有即时反馈，并且可以撤销：Toast 里的「撤销」、Ctrl/Cmd+Z、列表里的「撤销」。
6. **不打断人手上的事。** 不强制跳页，不弹阻断式对话框，冲突就地拍板。复查在后台完成，不推开布局。
7. **常用的好做，会丢东西的难误碰。** 推荐选项放在第一位并获得默认焦点。恢复高风险原句必须先选理由。重新生成收进「⋯」菜单，并且可以撤销。
8. **界面自己说明自己。** 用人话写状态，例如「还需你决定 3 件」「系统改过，点开可撤销」，不需要说明书。

## 1. Product Identity
- **Product Name**：Zhihu Bridge
- **One-Sentence Pitch**：把产品资料交给我们，拿走一份能直接发布的英文新品页。系统借助知乎上的工程语境避开直译误读，替你删掉没有依据的夸大说法；你只需要决定几件只有你知道的事。
- **Platform & Tech Stack**：
  - 前端：Vite + React + TypeScript（`app/web`）。新入口是 `index.html`，旧原型隔离在 `legacy.html`。
  - 后端：Python FastAPI（`app/server/bridge`）。
  - Stage 1 原型：零依赖的单文件 HTML。
- **Category**：B2B SaaS，是基于知乎知识增强的出海内容本地化与跨文化适配工具。

## 2. Target Audience & Context
- **Primary User**：大湾区智能硬件团队的创始人、产品负责人或海外市场负责人。他们熟悉参数，但不熟悉美式众筹叙事和广告声称的风险。时间少，不想学一套系统概念。
- **Usage Environment**：桌面优先（`1440×900`，兼顾 `1280×720` 和演示投屏）；手机（`375px`）上能看完并做完所有决定。
- **Emotional Tone**：省心（Effortless）、可信（Grounded）、可交付（Ready-to-Ship）。

## 3. Core User Flows
1. **主路径（一键 + 3 次判断）**：
   首页上传或拖入资料，或打开示例项目。系统依次完成五步：读资料、找事实、查知乎行业说法、写英文页、逐句检查，然后自动进入工作台第 1 步「产品资料」。用户在决定区处理 3 件事：
   - 一次确认系统读出的 4 条事实；
   - 机身重量二选一（系统给出推荐，但不替你选）；
   - Apple Health 计划功能的写法。

   流程条和顶栏状态胶囊随即变成「都已确认」「可以导出了」，点「导出交付」即可。同一个决定也可以在第 3 步正文的占位处、或第 4 步检查页里就地完成。
2. **核查与撤销**：
   - 第 3 步正文里的绿色虚线表示系统改过。点开能看到原句、原因和分层依据，可以「恢复原句」。高风险项恢复前须先选理由，并会记入检查报告。
   - 第 4 步「发布前检查」沿用 D 的详情：原句定位、为什么改、分层依据、修改对照。处置区提供「在英文页里看」和「恢复原句…」。
3. **编辑与自动复查**：
   - 点段落的「编辑」，可以选「保存」或「放弃」（Esc 放弃，Ctrl+Enter 保存）。
   - 保存后，这一段自动复查，约 1 秒出结果。
   - 新写进的风险说法（如 all-day battery、waterproof）会就地标红，并进入「需要你决定」。可以换成推荐说法，或者保留（须选理由）。
4. **知乎价值可见**：
   - 第 2 步保留 D 的桥接卡：知乎讨论 ⟷ 英文对照、直译可能引起的误解、系统怎么写、直译与本地化对比。卡片默认全部「在用」。
   - 第 3 步左栏是「洞察带来的改变」对比卡；点任意卖点，会高亮它用到的事实和知乎建议。

   关掉某条建议后，正文会立刻改回普通写法，也可以撤销。
5. **导出永不被阻断**：仍有未决定的事项时也能导出。这些地方在导出文件里写成 `[待确认]`，并列在检查报告中。导出时一起生成检查报告、中英口径表和知乎技术拆解草稿。草稿只给「复制」和「打开知乎」，不会自动发布。

## 4. Information Architecture & Screen Priority
| Screen | Primary Goal | Key Modules | Primary CTA |
| :--- | :--- | :--- | :--- |
| `/` 首页 | 5 秒看懂，马上开始 | 沿用 D：价值标题、三条原则、四步流程卡（最后一步「你拍板几件事」用琥珀色）、最近项目表。主按钮「上传产品资料，开始」，整块可拖放，也可粘贴文字，无表单 | 上传产品资料，开始 |
| `/projects/:id/run` 运行进度 | 让人放心等待 | 5 步进度，每步写出结果摘要；完成后自动进入工作台第 1 步 | — |
| 工作台顶部 | 随时知道还剩什么 | 状态胶囊（还需你决定 N 件 / 可以导出了，点一下直达）、导出交付；设置行（市场为静态文本，渠道、受众、语气为可改芯片）；四步流程条，每步下面写人话状态 | 导出交付 |
| 第 1 步 产品资料 | 只处理需要人的事实 | 左：原始资料（读不出的文件就地「粘贴文字 / 移除」）+ 系统已替你处理；右：产品事实三组：需要你决定（重量、Apple Health 两张决定卡并排）/ 资料写得明确的 4 条（一键确认，逐条「不对？」）/ 系统不会使用的 | 都对，确认这 4 条 |
| 第 2 步 知乎认知洞察 | 看见知乎如何改变英文 | 左：分析了哪些说法、数据说明、写作要点；右：桥接卡，底部「在用」开关 | — |
| 第 3 步 海外内容 | 看英文页，必要时编辑 | 左：依据（点卖点就高亮）+ 洞察带来的改变；右：5 段英文，带段落状态、「编辑 / ⋯」、绿色虚线与琥珀占位 | — |
| 第 4 步 发布前检查 | 核查系统做了什么 | 一行状态条；左：分组列表（需要你决定 / 系统已替你处理 / 你保留了原句 / 你已决定）；右：原句定位、为什么改、分层依据、修改对照、处置 | — |
| 导出抽屉 | 一次拿走全部交付物 | 状态说明（未决定项写成 [待确认]，可点「先去决定」）、英文页 Markdown 预览、一起生成好的附件（检查报告 / 中英口径表 / 知乎草稿） | 下载全部 |
| 生成记录与数据来源（页脚入口） | 给评委和开发者查看 | 每一步的生成方式、数据来源、额度 | — |

> **收敛约束**：
> - 以 D 为底只做减法：流程条、桥接卡、依据联动、检查详情全部保留。
> - 删除新建项目表单、逐行三段按钮、营销开关、采纳复选框、复检按钮与过期黄条、额度面板、KPI 大卡、问题筛选、常驻 Trace、内部编号与版本号。
> - 四步之间不强制顺序；状态胶囊始终指向下一件要做的事。
> - 小屏时主内容（决定区、桥接卡、英文正文）排在辅助信息之前。

## 5. Real Copy & Domain Data Seed
*案例全部是虚构产品，界面标注「示例产品 · 虚构」。原型中的知乎内容和英文参考都是示意，标注「示例数据【示意】」；正式版只能使用接口返回或用户提供的真实来源。*

- **首页标题**：把产品资料交给我们，拿走一份能直接发布的英文新品页
- **首页副标题**：面向美国 Kickstarter 的智能硬件新品。系统会读资料、查知乎上的行业说法、写英文页并逐句检查。你只需要决定几件只有你知道的事。
- **项目**：`PulseRing X1 智能指环`，Kickstarter 众筹页，科技早期支持者，专业克制。
- **原始资料（5 份）**：
  1. 产品说明 v1.2（.md）
  2. 硬件规格表 EVT3（.csv）
  3. 功耗与协议调试工程笔记（.txt）
  4. 中文预热营销初稿（.docx）
  5. 认证清单（.pdf）：扫描件读不出文字，未使用，提供就地「粘贴其中文字」入口。
- **需要你决定（3 件）**：
  1. 「这 4 条产品事实读得对吗？」包括：6 层 PCB、低功耗优化（无续航实测）、UART/BLE 调试（固件不开源）、5 ATM。可选「都对，确认这 4 条」，或逐条「不对？」后就地改写。
  2. 「机身重量写多少？」可选 3.6 g（9 号指围，推荐，来自规格表 EVT3）、3.2 g（产品说明 v1.2），或「都不对，我来填」。
  3. 「Apple Health 双向同步还没上线，怎么写？」可选「照实写：上市可导出，双向同步计划中」（推荐），或「先不提这个功能」。
- **系统已替你处理（4 处）**：
  1. 删掉「全天续航」「行业领先」（高风险，恢复须选理由）；
  2. 把「堆料」换成工程说法；
  3. 防水补上米和英尺，并写明不适合潜水；
  4. 没有写「医疗级 / FDA 认证」：这一项不可撤销，只提供「有证书？补充资料」。
- **保留理由预设**：已有实测数据，稍后补上；负责人确认保留；上线前会再改。
- **知乎帮你避开的 3 处误读**：
  - 堆料 → high-grade component selection
  - 底层协议调试 → protocol debugging — firmware is not open source（英文侧没有找到资料，标为「AI 推断 · 待验证」）
  - 极限压榨功耗 → power-optimized architecture
- **英文页**：标题和一句话介绍、4 条卖点、详细介绍、技术参数（续航写 Runtime testing in progress，不写时长）、FAQ（是否开源、是否医疗设备、重量、Apple Health）。

## 6. Hard Constraints
- **Trust floor（不可简化）**：
  - AI 判定与用户决定分开存储；模型不得写入用户决定。
  - 冲突必须由人拍板，系统只能推荐。
  - 没有依据的声称不进入英文页。
  - 系统自动修订只能让内容更保守，并且全部可撤销、留痕。
  - 不宣称法律合规，也不担保能通过审核。
  - 不自动发布到任何平台。
- **Accessibility**：
  - 达到 WCAG AA。
  - 状态由颜色、文字和图标共同表达。
  - 使用原生 `<button>` 和 `<dialog>`。
  - 弹层的默认焦点放在安全动作或推荐选项上。
  - 支持 Esc 关闭、Ctrl/Cmd+Z 撤销，以及 `prefers-reduced-motion`。
- **Source honesty**：依据统一放在点开后的弹层里，显示来源层标签（你的资料 / 知乎讨论 / 英文同类产品 / 官方规则提示 / AI 推断）和获取方式；示例数据、缓存和开发占位如实标注。
- **Layout**：
  - `1440` 下为两栏布局，沿用 D 的面板，各栏独立滚动。
  - `≤1100` 时变为单栏，主内容在前。
  - `375` 下无横向溢出，流程条可以横向滑动。
- **Network**：Stage 1 HTML 零外部依赖，字体以 base64 内嵌，断网双击可用，font-check 徽章全部显示 ✓。
- **Human gate**：用户亲自在浏览器查看并确认后，才推进 `DESIGN.md` 与正式开发。
