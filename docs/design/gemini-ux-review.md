# Zhihu Bridge 交互、文案与流程审查报告

> 审查对象：`direction-d.lite.html`、`PRODUCT.md`、`Zhihu_Bridge_后续开发计划_V1.3.md`  
> 用户：大湾区智能硬件品牌市场/众筹负责人（美国 Kickstarter 首发）｜最高原则：**复杂留给系统，体验至高无上**

---

## 1. 总判断

当前设计把后端审计状态机原样摊给了市场负责人。最让用户累的 3 件事：
1. **逐条机械点击过多**：无冲突事实也要逐行点“确认”再拨“营销开关”；洞察卡要逐条勾“采纳”；审校采纳系统建议后还得手动按“复检”，一次完整流程需 30+ 次点击。
2. **跨页折返且不可撤销**：在 Tab 1 改事实会顶出黄条顶跳布局；在 Tab 3 点红线句被甩去 Tab 4，在 Tab 4 点“手动修改/解决冲突”又被甩回 Tab 3/Tab 1；审校一旦处置彻底锁死无法撤销。
3. **工程黑话铺满主视野**：`事实集 v4`、`Brief v2`、`curated_demo`、`zhihu_search` 额度表、`调试 Trace`、6 种审校状态与 5 种来源图形图例占满主界面，业务用户必须先学系统概念才能干活。

## 2. 逐原则问题清单

### 原则 1：系统能判断的，不留给用户
1. **Tab 1 事实表逐行双操**（P0）｜**在哪**：`#p-materials .facts`、`syncFactRow`（`L654-715, 1186-1205`）。**违反**：资料已明确支持且无冲突的 `F-01/03/05` 仍需先点“确认”再拨“可用于营销”，且与冲突项混排。**改法**：自动分为「需你拍板（3 项）」（冲突/待定/无依据）与「资料明确支持（4 项）」，后者给「一键全部采信并写入宣传页」；单行点「采信」默认开启写入宣传页。
2. **采纳建议后仍要手动点「仅复检受影响模块」**（P0）｜**在哪**：`#staleBanner`、`#rereviewBtn`（`L615-619, 1317-1333`）。**违反**：系统已明确知道只改动了单个模块，却弹黄条逼用户手动按复检。**改法**：接受建议或保存单模块编辑后，800ms 防抖自动在后台局部复查并刷新为「已通过」或剩余风险数，取消单模块手动复检黄条。
3. **Tab 2 暴露接口额度估算器**（P1）｜**在哪**：`#p-insights`「检索额度预估」（`L737-749`，含 `zhihu_search` 等接口名）。**违反**：缓存复用与配额调度是系统职责，不该让市场人员算公网剩余次数。**改法**：移出主区，默认走缓存；仅点击「刷新检索」触发限额时才弹窗引导连接个人知乎账号或用示范数据。
4. **新建项目弹窗放 2 个不可选下拉框**（P2）｜**在哪**：`#createDlg` 市场/语言下拉（`L1003-1004`）。**违反**：MVP 锁定美国·美式英语，仍放两个表单格让人确认。**改法**：替换为弹窗顶部一行静态说明：`面向美国市场 · 美式英语`。

### 原则 2：此刻没用的，就不出现
1. **顶栏主位常驻「调试 Trace」**（P0）｜**在哪**：`.chrome [data-open="traceDlg"]`、`#traceDlg`（`L594, 1064-1079`）。**违反**：`extract`/`guard.py`/`curated_demo` 属研发日志，却紧挨主按钮「导出交付」。**改法**：移入右上角「⋯」更多菜单 → 「生成记录与数据源」。
2. **Tab 4 顶部 5 个 KPI 大卡片重复占位**（P1）｜**在哪**：`#p-review .kpis`（`L967-973`）。**违反**：步骤条已报数量，Tab 4 又用高卡片重复展示，挤压核心对照改写区高度。**改法**：压成一行紧凑状态条（`待处理 5 项（2 高风险）· 已解决 0/5` + 5 个模块小点）。
3. **Tab 3 左栏常驻“洞察带来的改变”与“不可用于营销”清单**（P1）｜**在哪**：`#p-content .lchip.off`、`.change`（`L883-905`）。**违反**：前者是评委展示板，后者仅误引用时才需关注，日常占去半屏。**改法**：“不可用于营销”默认折叠（误引用时自动展开标红）；“翻译前后对比”改为顶栏轻量按钮「查看翻译对比」按需展开。
4. **首页提前塞入 5 种来源层图例与合规宣言**（P2）｜**在哪**：`#view-home .pipeline .tags`、`.principles`（`L526-542`）。**违反**：用户未建项目先看一堆色块图例。**改法**：首页只讲 4 步业务价值，来源标签随证据就地展示。

### 原则 3：能替人做的，就直接做
1. **高价值洞察卡默认不采纳**（P0）｜**在哪**：Tab 2 `I-03`（极限压榨功耗，`L818-847`）默认未勾选。**违反**：系统已识别出高风险黑话却默认不采用，还要求逐张打勾再点「按 Brief 生成海外内容」。**改法**：高相关洞察默认全部启用（用户只对不同意的卡点「暂不采用」），实时汇总到下方“英文写作要点”，省去中间步骤。
2. **冲突项无法在审校页就地拍板**（P0）｜**在哪**：Tab 4 `R-03` 按钮「去产品资料决定冲突组 W-1」（`L1251, 1268`）。**违反**：点完强跳回 Tab 1 自己找行，选完还要回 Tab 4 且正文未更新。**改法**：在 `R-03` 卡片内直接给单选：「采用 3.2 g（产品说明）/ 采用 3.6 g（9 号指围）/ 暂写量产前确认」，就地同步更新事实档案与正文。
3. **审校缺少一键批量采纳与自动跳下一条**（P1）｜**在哪**：Tab 4 `#issueList`、`act()`（`L976-985, 1245-1253`）。**违反**：4 条已有明确安全改法仍需逐条点选，且处置后停在原地需反复挪鼠标点左栏。**改法**：列表顶部增「一键采纳推荐改法（4 项）」；单条处置后 0.6s 自动跳下一条待处理项。

### 原则 4：同一件事，处处一样
1. **同类操作叫法与控件分裂**（P1）｜**在哪**：Tab 1「你的决定」vs `PRODUCT.md`「我的决定」；Tab 1「修改」vs Tab 3「编辑」vs Tab 4「手动修改」；Tab 2 复选框「采纳进 Brief」vs Tab 1 开关「可用于营销」vs Tab 4 主按钮「接受建议改写」。**违反**：概念与交互控件不统一。**改法**：全站统一用词（见第 4 节术语表），修改文案统一叫「编辑」。
2. **橙黄色同时代表 6 种语义**（P1）｜**在哪**：`--status-warning`（`L44, 105, 110, 121`）同时用于演示标、开发占位、AI 推断、冲突、中风险、审校过期。**违反**：满屏同色黄标分不清提示还是真风险。**改法**：演示标与开发占位改中性石板灰描边；AI 推断改淡紫灰虚线；橙黄只给冲突/中风险，红只给高风险/错误。
3. **Tab 3 模块操作栏与 Tab 1 步骤计数不一致**（P1）｜**在哪**：`#m-headline..#m-faq`（`L910-951`）按钮时有时无；`#t-materials small`（`L608`）数字写死不随 `render()` 更新。**违反**：操作位不可预测，改完事实顶部仍显示“2 待决定”。**改法**：5 模块统一右置「编辑」（参数表改为「去改事实」）+「⋯（重新生成/历史版本）」；Tab 1 步骤数接入动态状态。

### 原则 5：按下去有回应，再按能收回
1. **审校处置全部是单行道，无法撤销**（P0）｜**在哪**：Tab 4 `apply()`、`renderDetail()`（`L1241-1244, 1272-1275`）。**违反**：`m.replaceWith(span)` 直接销毁原 `<mark>`，处置后只剩静态文字，误点无法恢复原句。**改法**：保留原句与操作栈，处置栏与 Toast 均提供「撤销」按钮，一键还原原文并重开问题。
2. **Tab 1 点「修改」不弹输入框**（P0）｜**在哪**：`.seg button[data-v="edited"]`（`L1200-1203`）。**违反**：只把按钮变黑并加版本号，未提供编辑文本入口。**改法**：点击后行内展开输入框 + 「保存 / 取消」，保存才生效并可撤销。
3. **Tab 3 编辑无「放弃」且原型存在多处死按钮**（P1）｜**在哪**：`[data-edit]`（`L1232-1238` 存了 `snap` 却无取消按钮）；`粘贴文本`、`添加概念`、`重新生成`、导出抽屉按钮等均无反馈（`L634, 734, 748, 910, 1059`）。**违反**：按下去无回应或改乱无法撤回。**改法**：编辑态并排「保存 / 放弃」；所有可见按钮必须有明确 loading 与结果反馈。

### 原则 6：不打断人手上的事
1. **内容页与审校页互相强制跳 Tab**（P0）｜**在哪**：`mark.risk[data-goto]` 强制 `showTab('review')`（`L1228-1231`）；Tab 4 `act('manual')` 强制 `showTab('content')`（`L1250`）。**违反**：正在读文案或清审校清单时被整页切走，心流断裂。**改法**：Tab 3 点红线句就地弹 Popover（看原因 + 一键替换）；Tab 4 点「手动修改」就在原句框内直接编辑保存。
2. **Tab 1 逐行点选时顶栏黄条顶跳页面**（P0）｜**在哪**：`bumpFactSet()` 触发 `#staleBanner` 显隐（`L1194-1205, 1317`）。**违反**：点第一行顶部突然撑出 44px 黄条，表格整体下移导致误点，且连续弹版本号 Toast。**改法**：在 Tab 1 操作时不顶出 Banner，仅在 Tab 3/4 标签加安静红点，离开 Tab 1 或点下一步时统一同步。
3. **低风险忽略被必填输入框阻断**（P1）｜**在哪**：Tab 4 `#dismissNote`（`L1283, 1289`）。**违反**：`R-05`（5 ATM 换算建议）这类低风险项也强迫打字才能忽略。**改法**：低/中风险一键忽略（备注选填）；仅高风险忽略提供 3 个单选预设理由（「已补测试」「负责人确认」「上线前删改」），点选即过。

### 原则 7：常用的操作好做，会丢东西的操作难误碰
1. **「确认 / 修改 / 驳回」紧挨且双击「确认」会清空决定并关掉营销开关**（P0）｜**在哪**：Tab 1 `.seg`（`L661, 1201`：`decision===v ? 'pending' : v`）。**违反**：手滑多点一下已确认项直接回退未决定并触发全站审校过期，且高危「驳回」与常用「确认」等权紧贴。**改法**：取消“再点确认即反选”；主按钮「采信」、次按钮「编辑」，破坏性的「不用此条」拉开间距或收进「⋯」。
2. **「重新生成」紧挨「编辑」且无防覆盖保护**（P1）｜**在哪**：Tab 3 模块标题栏（`L910, 930, 951`）。**违反**：手滑点中直接覆盖人工精修稿。**改法**：收入「⋯」菜单；模块有手改记录时，重新生成先出新旧对比再确认替换。
3. **各 Tab 缺底部「下一步」主按钮**（P1）｜**在哪**：Tab 1/3/4 底部无推进 CTA，仅 Tab 2 有（`L861`）。**违反**：高频主路径需回头找顶部步骤条。**改法**：各 Tab 右下角固定下一步主按钮（进入跨文化洞察 → 生成英文页 → 查看自查 → 导出交付包）。

### 原则 8：界面自己说明自己
1. **裸字母编号占满主界面**（P1）｜**在哪**：卖点胶囊 `F-01`/`I-01`（`L921`）、`W-1`（`L678`）、`事实集 v4`（`L605`）。**违反**：新用户不知缩写含义。**改法**：改为人话短标签（如 `依据：6 层 PCB 规格`、`知乎建议：堆料改写`），编号退居悬浮详情。
2. **解析失败文件无就地补救按钮**（P1）｜**在哪**：Tab 1 `PulseRing_X1_认证清单.docx`（`L632`）。**违反**：文字让人粘贴正文，却没给按钮。**改法**：行内直接给「粘贴文字替代」与「移除」按钮。
3. **「知乎知识回流包」「演示语料 · 预运行」表意晦涩**（P1）｜**在哪**：导出抽屉（`L1020, 1034`）、顶栏 `.conn`（`L593`）。**违反**：市场负责人看不懂“回流包”收益与“预运行”含义。**改法**：分别改为「双语口径与国内预热草稿」（顶栏说明一鱼两吃价值）与「示例项目（示范数据，可自由操作）」。

## 3. 流程简化提案

### 3.1 六处高摩擦决策减负

| 痛点环节 | 简化策略（默认 / 批量 / 删除） |
| :--- | :--- |
| **1. 事实表逐行“确认+营销开关”** | **分组 + 合并 + 批量**：仅将冲突/存疑/无依据项置顶单点拍板；资料明确支持项提供「一键全部采信并写入宣传页」；单行点「采信」默认即允许对外宣传，“仅内部参考”降为次级开关。 |
| **2. 洞察卡逐条勾“采纳”** | **默认启用（opt-out）**：高相关防踩坑洞察默认开启，用户仅对不同意的卡点「暂不采用」；实时自动汇总到“英文写作要点”，取消手动生成 Brief 步骤。 |
| **3. “仅复检受影响模块”手动按** | **删除常规手动动作**：单模块编辑或采纳建议后，800ms 防抖后台自动局部复查并刷新状态；仅当事实大改影响多模块或网络失败时才显示「同步更新并重查」。 |
| **4. 审校问题 6 种状态** | **前端收束为 2 主态**：列表与筛选只显示「待处理 / 已解决」；规则项用行动提示“需你核实规则”替代独立状态名，解决后统一绿勾 + 淡灰小字（已按建议改写/已编辑/已核实/已忽略）；后端保留 6 态供报告导出。 |
| **5. 驳回/忽略必填理由** | **分级 + 快捷单选**：事实排除、修改备注、审校低/中风险忽略全部免填理由；仅高风险忽略给 3 个一键预设单选理由，不强迫打字。 |
| **6. Trace / 额度表 / 来源图例** | **移出主流程**：Trace 藏入右上角「⋯」；额度估算器仅在刷新触发限额时弹窗提示；删掉独立图例，在每条依据旁直接用简明中文写明出处。 |

### 3.2 理想的「一键主路径」

从上传资料到拿到交付包，用户最少只需做 **3 次真正的业务判断**：
1. **导入资料，一键分析**：填入产品名、上传/粘贴资料 → 点「开始分析」（系统后台自动串联事实提取、冲突识别、知乎跨文化建议与写作要点汇总）。
2. **判断 ① · 拍板争议事实（~30 秒）**：只处理置顶的 2–3 条冲突/待定项（如重量选 3.2 g 还是 3.6 g、OTA 写不写），其余明确事实点 1 次「全部采信」→ 点「生成英文发布页」（默认启用知乎防踩坑建议，并在生成后**自动完成发布前自查**）。
3. **判断 ② · 浏览英文稿并微调（~1 分钟）**：通读 5 大模块，遇标红句可在行内浮层一键替换，想看或取消某条知乎建议可进 Tab 2 调整。
4. **判断 ③ · 清零高风险项并导出（~1 分钟）**：在 Tab 4 对有明确改法的项点 1 次「一键采纳推荐改法」（系统自动局部复查变绿），就地拍板剩余冲突/规则项 → 点「导出交付包」，一次拿走英文终稿、自查报告，以及顺手生成的双语术语口径表与知乎预热草稿。

## 4. 文案重写与统一术语

### 统一术语（消灭工程腔）
- `事实集 v4` → **已确认产品资料**（版本号收进历史）
- `stale` / `审校已过期` → **有改动，待复查**（单模块自动复查时直接显示「复查中…」）
- `复检` / `仅复检受影响模块` → **重新检查改动部分**
- `内容策略 Brief` → **英文写作要点**
- `宣传声称 / 事实一致性 / 跨文化适配 / 市场与平台规则` → **夸大风险 / 事实核对 / 表达地道度 / 平台与法规提示**
- `处置` → **处理方式**（按钮区标题用「怎么改」）
- `知乎知识回流包` → **双语口径与国内预热草稿**

## 5. 必须保留的复杂度与“低负担”实现法

以下 5 条关乎可信度与合规底线，不能简化掉，但须用低摩擦方式承接：

1. **AI 判断与人工决定严格分离**（模型严禁代写 `user_decision` / `marketing_allowed`）：把“资料明确支持且无冲突”的事实分组，让用户点 1 下「全部采信」完成批量人工确认，既不越权又少点 7 次。
2. **未确认/冲突/无依据事实绝不进宣传页，缺失与冲突只出占位符**：守住底线，但让用户在 Tab 1、Tab 3 参数表、Tab 4 审校卡任何一处看到冲突都能就地二选一拍板并自动回填，免去来回切页。
3. **来源权责分层与获取方式诚实标注**（企业资料=唯一事实；知乎=语境非参数；演示/缓存不冒充实时；AI 推断标待确认）：平时只显示简短人话出处（`硬件规格表` / `知乎讨论 · 示范数据` / `AI 分析 · 待确认`），完整 URL 与抓取时间折叠在点击浮层里，平时干净、深挖可查。
4. **内容或事实变动后禁止继续显示“审校已通过”**（版本推算不存可变布尔）：底层机制不变，但前台改由系统自动触发单模块静默复查，用户只看到“保存后 1 秒自动复查完成”，把状态机复杂度消化在后台。
5. **不宣称法律认证、知乎草稿绝不自动发布**：把每张审校卡重复的免责长文收束为页底一行 + 导出报告固定声明；知乎草稿区直接给「复制全文」+「打开知乎去发布（新窗口）」，用直观动作传递边界而非反复说教。
